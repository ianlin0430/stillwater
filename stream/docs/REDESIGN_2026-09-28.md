# Stillwater Reef 重新定案（2026-09-28）

> 使用者在 2026-09-28 用 grill-me 重新整理需求，參考 [Zen Aquarium](https://store.steampowered.com/app/3479140/Zen_Aquarium/)（Steam 上的放置型魚缸：純觀賞、零管理、魚缸慢慢長起來），但我們做 **2D 像素版**。**本文件取代之前所有和魚種、場景、互動有關的規格**；和本文件衝突的舊段落（`CODEX_FRONTEND_PLAN.md` §3.7–§3.10、`BACKEND_SNAPSHOT_EVENTS.md` 的 tang/firefish/blenny 內容）一律以本文件為準。

## 1. 定案

| 項目 | 決定 |
|---|---|
| 核心 | 打開就能放著看，沒有壓力、不用照顧。生態藏在背後：魚會出生、長大、自然老去，但**絕不會因為沒人管而餓死或死光**。 |
| 引擎 | 留在 Godot 4.6.3。 |
| 畫面 | 視窗可自由縮放，像素一律**整數倍放大**、不糊；一鍵全螢幕。**前景（視窗在最前面）60 FPS，看得到但沒專心時 30 FPS，完全隱藏時不畫**，並做**像素對齊**（粗像素不在兩格之間抖）。CPU 上限等實測後再定。 |
| 轉身 | 只用側面那一張圖，像紙片翻面（寬度照 `abs(cos(heading))` 平順變窄、中間翻面）。**沒有中間／正面姿勢。** |
| 聲音 | **不要聲音。** |
| 魚種（4 種） | `green_chromis`（保留）、`clownfish`（小丑魚）、`seahorse`（海馬）、`royal_gramma`（皇家范魚）。**拿掉** `yellow_tang`、`purple_firefish`、`lawnmower_blenny`。 |
| 場景 | **礁岩**、**沉船花園**兩個。同一群魚、同一份存檔；切換時整幕淡出淡入，魚在新場景裡安頓（小丑魚回到新場景的海葵）。 |
| 裝飾 | 每個場景約 4–6 個**固定槽位**，每槽可選幾種款式或空著。裝飾**會影響魚**：當**躲藏／休息點**，也是**障礙物**（魚會繞過，不會穿過）。裝飾不增加食物、不改變魚的數量上限。 |
| 必備裝飾 | 每個場景固定有一個**海葵**（小丑魚的家）和一叢**能勾的水草**（海馬休息），可以換款式，不能拿掉。 |
| 老死 | 安靜消失：老魚游到畫面邊緣或裝飾後面，慢慢淡出。不下沉、沒有屍體。 |
| 互動 | 保留**餵食**（不餵也不會餓死，每天有上限）、**游標引魚**、**敲玻璃**（魚受驚散開、躲進裝飾）。**拿掉點魚看資訊**。 |
| 存檔 | 正式版從**全新世界**開始，舊格式不轉換。舊的 `Stillwater Stream` 資料夾照樣不碰。 |

## 2. 四種魚的個性（行為草案，確切欄位以 backend 落地後的 `BACKEND_SNAPSHOT_EVENTS.md` 為準）

| 魚 | 樣子 | 會做什麼 | 用到的裝飾 |
|---|---|---|---|
| `green_chromis` | 小、藍綠、成群 | 中層成群游、一起轉向；夜裡就地懸停休息；受驚散開再聚回來。 | 夜裡可靠在躲藏點旁休息；繞過障礙物。 |
| `clownfish` | 橘白條紋 | 大部分時間在海葵裡和附近扭動游（小幅來回）；離開一小段去吃東西就回來；受驚鑽進海葵；夜裡窩在海葵裡。 | 海葵（必備）是家。 |
| `seahorse` | 直立、慢 | 用尾巴勾著水草或裝飾，身體輕輕搖；偶爾放開、直立慢慢漂到另一個能勾的地方；背鰭細細地扇。 | 能勾的水草（必備）與可勾的裝飾。 |
| `royal_gramma` | 前紫後黃、小 | 在岩洞或躲藏點的洞口附近徘徊、進出；受驚鑽進去。 | 躲藏點（岩洞類裝飾）；沒有時就待在岩石邊。 |

## 3. 分工

### Codex（前端與美術）——現在就可以開始
1. **新魚美術**：`clownfish`、`seahorse`、`royal_gramma` 的低像素側面圖，風格、像素粗細、配色數量跟已核可的 chromis 一致（`assets/reef/PROVENANCE.md` 那張低像素 atlas）。先出一張四種魚並排的風格板給使用者核可，**核可前不要裝進正式版**。
2. **紙片式轉身**（見 `CODEX_START_HERE.md` 2026-09-28 那條）：拿掉中間／正面姿勢。
3. **像素對齊與畫面**：整數倍放大、可縮放視窗、一鍵全螢幕、像素對齊（不在兩格間抖）。FPS 切換（60／30／不畫）由 Claude 做，你只要確保 60 FPS 下動畫是用實際 delta 走、不依賴固定 30。
4. **沉船花園場景**：延續你的沉船藻類花園預覽，做成正式場景；礁岩場景也要能當正式場景用。兩個場景的背景、前景、光線風格一致。
5. **裝飾美術**：每個場景的海葵、能勾的水草各 2–3 款；躲藏點（岩洞、貝殼、沉船碎片等）與障礙物各幾款。
6. **裝飾與場景介面**：選場景、點槽位換款式或清空；介面要安靜、不擋魚。切換場景的淡出淡入。
7. **新魚動畫**：照上表的個性做（小丑魚在海葵裡扭動、海馬勾住搖擺與直立漂移、皇家范魚洞口進出），全部照使用者方向：**流暢自然、不寫實**，所有切換 ease in／out，不抖、不突然換姿勢。老死的「游到邊緣淡出」。
8. **等 Claude 的 backend 落地後**再移除 tang／firefish／blenny 的前端程式與測試（在那之前 backend 還會送這三種魚）。

**邊界**：不要改 `stream_world.gd`、`stream_store.gd`、生態測試、`.github/`；缺欄位就寫給 Claude。開 app 只能用 `-- --qa` 或 `-- --persist-qa=<id>`。只 commit 自己的檔案。

**驗收**：每一步交 1.65× 對照短片或風格板給使用者判斷；前端測試全綠。

### Claude（後端）
1. **場景資料**：一個場景檔描述地形（床面曲線、水層範圍）、槽位位置與每種裝飾的效果（躲藏點、障礙物範圍、可勾點），後端和前端都讀它。**槽位座標要對齊 Codex 的背景，Claude 會先出格式，再和 Codex 對座標。**
2. **新魚行為與生態**：四種魚的行為、上限、繁殖、老死；先用離線探測決定上限（規則：先量再定數字，不為了過關調門檻）。確保不會餓死、不會死光。
3. **裝飾影響魚**：躲藏／休息點、障礙物（繞過而不是穿過）；海葵與水草必備。
4. **老死安靜消失**：老魚最後會游去邊緣或裝飾後面，前端再淡出。
5. **切換場景**：同一群魚搬到新場景的對應位置。
6. **全新世界**：拿掉舊魚種的存檔升級路徑，新格式存檔。
7. **60／30／不畫的 FPS 切換**與耗電實測，定出新的 CPU 上限。
8. **驗證**：更新所有測試；兩個場景、各種裝飾組合、有餵／不餵，都跑雲端 180 天。
9. 更新 `BACKEND_SNAPSHOT_EVENTS.md` 給 Codex。

## 4. 順序

1. 使用者核可新魚風格板（Codex） ∥ 場景檔格式與新魚後端（Claude）。
2. 對齊場景座標與槽位（兩邊一起）。
3. 新魚動畫、裝飾介面（Codex） ∥ 裝飾效果、老死、切場景、FPS（Claude）。
4. 雲端 180 天驗證 → 使用者看完整對照片 → 打包 → 使用者親手測（Cmd-Q、睡眠喚醒）→ 30 分鐘效能驗收。
