# 自我維持的生態系：計畫與規則(2026-09-22)

本文件定下 Stillwater Stream 生態模型第二版(存檔 v2)的規則。決策來自 2026-09-22 與使用者的逐題確認。**本階段不做任何美術**:植物只在模擬裡存在，並透過 snapshot 提供數值，畫面之後另外處理。

## 已確認的決策

| # | 決策 |
|---|---|
| 1 | 以在地的生命週期為主：個體在池裡長大、繁殖、變老、死亡，後代留在池裡 |
| 2 | 數量由食物控制為主，另有物種空間上限：蝦 8、threadfin 5、hatchetfish 5;總數硬上限 24 不變 |
| 3 | 移入以「救援」為主(物種 ≤2 隻時平均 3–5 天一隻),平常約 3 週一次;沒有成年個體隨機離開;只有超過空間上限時，幼體才漂到下游 |
| 4 | ~~捕食：幼蝦離開育幼區且沒有莖草掩護時，偶爾被魚吃掉;事件文字不血腥~~ 已由 2026-09-23 決策取代：完全沒有捕食(見文末) |
| 5 | 壽命：蝦約 120 天、魚約 180 天(個體有 ±15% 差異),成熟時間不變;開局年齡錯開，第一批老死出現在 60 天內 |
| 6 | 能量來自光，養分在池裡循環，溪流只做少量交換 |
| 7 | 植物：水面浮萍、底床莖草、石頭上的藻類和生物膜;本階段只做模擬 |

## 規則

### R1 物質守恆
- 所有生態物質用同一種單位(養分單位)計量。
- 物質池:
  - `nutrients`:溶解養分
  - `stem`:底床莖草
  - `floating`:水面浮萍
  - `biofilm`:藻類和生物膜
  - `microfauna`:浮游小生物
  - `detritus`:碎屑
  - 動物的 `body` + `energy`
- 光提供能量但不提供物質。植物生長時，物質從 `nutrients` 轉到植物。
- 物質只能經由下列管道進出這個水池，並記入 `ledger.in` / `ledger.out`:溪流交換、移入、漂到下游、舊存檔的 crayfish 離開。
- 動物的呼吸和代謝不再讓物質消失。消耗掉的能量 65% 變成 `nutrients`(排泄),35% 變成 `detritus`。
- 誤差 `residual()` 必須 < 1e-5。

### R2 光照
- 模擬自己推進時間：每個生態 tick(1 分鐘)讓 `light_hour` 前進 1/60 小時。在前景時,`main.gd` 仍然會用本地時間校正它。
- 自然光為 `L = clamp(sin((hour-6)/12·π), 0, 1)`。
- 水面以下的光為 `L_sub = L·(1 − 0.5·floating/floating_max)`,也就是浮萍會遮光。
- 觀賞燈(viewing light)不影響模擬。

### R3 植物與生物膜的生長(每 tick)
- 生長：`G = r·P·光·N/(N+K_N)·(1−P/P_max)`,G 從 `nutrients` 扣除，加到該植物池。
- 衰亡：`P·m` 轉成 `detritus`。
- 各植物用的光：
  - 浮萍用 `L`
  - 莖草和生物膜用 `L_sub`
- 生物膜的上限會隨莖草變多而提高(附著面積變大):`biofilm_max = B0 + b·stem`。
- 每個植物池都有一個很小的「種源」下限(模擬溪流帶來的孢子和碎片):低於下限時，由溪流補到下限，並記入 `ledger.in`。所以植物不會永久滅絕，但可以被吃到很少。

### R4 浮游小生物與碎屑
- 浮游小生物吃碎屑裡的細菌：`M` 的生長為 `r_M·M·D/(D+K_D)·(1−M/M_max)`,從 `detritus` 扣除。死亡 `M·m` 的 50% 回到 `nutrients`、50% 回到 `detritus`，避免無動物時養分被此物質池囤住。
- 碎屑分解：`D·k` 轉成 `nutrients`。

### R5 溪流交換
- 流入：固定的少量 `nutrients` 和 `microfauna`。
- 流出：`nutrients`、`microfauna`、`detritus` 各按比例流出;浮萍有極少量漂走;莖草和生物膜不會流出。
- 參數要調到：沒有動物時，池子會收斂到穩定狀態，不會無限累積，也不會流乾。

### R6 動物進食
- 蝦主要吃 `biofilm`,生物膜少的時候改吃 `detritus`。
- 兩種魚吃 `microfauna`。
- 攝食量採飽和曲線：`bite/1440 · X/(X+K_food)`,並受「還能吃多少」限制。吃進去的 80% 變成 energy,20% 變成 detritus。

### R7 繁殖
- 條件：
  - 成熟的母、同種成熟的公
  - `energy > 0.74·reserve`
  - 冷卻時間已過
- 每 tick 的繁殖機率為 `breed/1440 × 食物因子`,食物因子為 `X/(X+K_food)`,所以食物越少越難繁殖。
- 出生時如果該物種已經達到空間上限(8/5/5)或總數達到 24,幼體改為漂到下游，記成 `dispersal` 事件並計入 `ledger.out`。

### R8 死亡
- 餓死:`energy` 耗盡。
- 老死：每隻個體出生時決定 `lifespan`,為物種壽命(蝦 120、魚 180 天)×(0.85–1.15),由世界的 rng 決定。
- 屍體全部轉成 `detritus`。

### R9 捕食(非血腥)——已於 2026-09-23 移除，以下僅保留為歷史
- 對象：還沒成熟的蝦。以下情況受保護：
  - 在育幼區(`|x−640| ≤ 95`)
  - 正在躲藏或脫殼
  - 被莖草掩護：保護機率 = `stem/stem_max × 0.6`
- 條件：魚本身有點餓(`hunger > 0.3`)。前景時要靠近才會發生;離線時改用機率。
- 被吃的幼蝦：70% 的物質變成魚的 energy(不超過 reserve),其餘變成 detritus。事件寫成「Silk caught a young shrimp.」這類文字。
- 頻率調整目標：每 180 天發生 3–20 次。

### R10 移入與離開
- 救援移入：某物種 ≤ 2 隻時，每小時機率約 1/96(平均約 4 天一隻)。
- 一般隨機移入：每小時機率約 1/504(平均約 3 週一次),而且要該物種未滿上限、總數 < 18。
- 沒有成年個體隨機離開。

### R11 開局
- 物質池從接近平衡的數值開始。
- 年齡錯開：蝦 25–100 天、魚 40–150 天。

### R12 存檔 v2 與舊存檔升級
- `VERSION = 2`。
- `validate()` 同時接受 v1(舊的欄位組合)和 v2。
- `restore()` 會把 v1 升級：
  - 補上新的物質池，用開局種源值，差額記入 `ledger.in`
  - 替每隻個體補上 `lifespan`
  - 舊存檔裡的 crayfish 記成離開
- 升級時，個體的 id、名字、譜系都不能變。

### R13 效能與邊界
- 每 tick 的計算量是 O(動物數 + 物質池數)。
- 72 小時補算要在 2 秒內完成。
- 模擬不讀取任何畫面狀態。
- snapshot 會帶出所有物質池，供之後的植物美術使用。

## 驗收(自動化測試)

`tests/long_run.gd`:3 個種子(42、812、240921)× 180 天，每次都要符合下表。

| 項目 | 標準 |
|---|---|
| 產生後代數 | 留在池內的出生 + 漂往下游的後代 ≥ 20；兩者仍分開報告 |
| 在地世代更替 | 留在池內的出生 > 移入，不把漂走的後代計入此項 |
| 老死 | ≥ 5,第一隻出現在 60 天內 |
| 餓死 | < 老死 |
| 幼蝦被吃 | ~~3–20 次~~ 2026-09-23 起為 0 次 |
| 總數 | ≥ 80% 的取樣日落在 12–18,任何時候都 ≤ 18 |
| 物種存在 | 三種都要在 ≥ 95% 的天數存在;消失後 30 天內回來 |
| 成年個體隨機離開 | 0 |
| 物質守恆 | 誤差 < 1e-5 |
| 植物 | `stem`、`floating`、`biofilm` 在 ≥ 95% 的取樣日高於各自上限的 5% |

另外還有一個 365 天的穩定性測試：不能有物種永久消失，誤差 < 1e-5。

### 交接決策與校準紀錄

接續 Claude 的交接採用選項 A，門檻確認的是持續繁殖，因此計算後代個體數（不是繁殖事件數，一次事件可有多隻）。不降低食物來製造空位，也不把留下來的出生數與漂走數合併後隱藏。原本「在地出生大於移入」的獨立要求保留。

目前校準值：每日溪流流入 nutrients 0.7、microfauna 0.35；浮萍 r=1.3、m=0.025；攝食半飽和常數蝦 6、魚 10；PREY_RATE=0.3。交接前後沒有再調整這些參數。無動物收斂測試觀察 360 天，生物膜恢復觀察 40 天，原比較門檻不變。

`tests/test_world.gd` 新增的單元測試:
- 沒有光時植物不長;浮萍會遮光
- 沒有動物時，物質池會收斂，而且守恆
- 生物膜被吃光後會長回來(恢復)
- 達到空間上限時，後代漂到下游
- 育幼區和莖草會保護幼蝦
- 每隻個體的 lifespan 在範圍內
- 救援移入會發生
- v1 存檔升級後，id、名字、譜系保持不變，而且守恆
- 同一個種子、同一種模式下可以重現

### 2026-09-23 決策：移除捕食(取代決策 #4)

使用者最終決定：Stillwater Stream 完全移除捕食，任何動物都不吃其他動物，即時與離線都一樣。出生、成長老死、餓死、幼體漂往下游、救援移入、個體身分與譜系全部保留；蝦的 `Retreating` 受驚短衝與捕食無關，保留。

- 移除：`_predation`、`exposure()`、`PREY_RATE`、`PREY_RANGE`、`PREY_DIVE`、`OFFLINE_ENCOUNTER`、`NURSERY_X/HALF/SHARE`、`feeding` 事件、`death` 事件的 `target`。育幼區只被捕食使用，所以一起移除；脫殼時的躲藏(`shelter`、`Molting`)不依賴育幼區，保留。
- 存檔相容：容器與 schema 不變(`VERSION` 仍為 2)。`totals.predation` 仍是必填欄位，舊存檔的數值原樣保留、不再增加；舊存檔裡的 `causes.predation`、archive 的 predation 死亡與 `feeding` 事件仍通過 `validate()`/`restore()`。
- 驗收：`幼蝦被吃` 改為 0 次(`ok.predation=run.predation==0`)，移除 `predation_conditions` 稽核。其他門檻一律不變。
- 校準值 `PREY_RATE=0.3` 已失效；其他校準值不動。
